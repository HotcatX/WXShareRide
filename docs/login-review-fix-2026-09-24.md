# 登录页审核整改验收

针对用户提供的审核意见：登录环节需要显著有效的取消、拒绝或返回路径，不能强迫登录后才能体验。

## 原因和修改

- 旧登录页的游客按钮与登录按钮共用隐私未勾选灰态；`onGuestTap`也要求先勾选隐私协议，导致跳过入口实际被拦住。
- 保留原有两按钮结构，将游客入口改为高对比的“暂不登录，先浏览”。未勾选隐私政策、登录请求尚未返回时均可直接使用，不触发登录或个人资料查询。
- 登录页标题改为“欢迎使用”，说明“浏览公开行程无需登录”，系统导航标题和返回控件采用黑色。
- 退出时清理待继续的预约动作与登录提示，仅返回公开来源页面；登录页、发布页和其他私人目标回退首页。退回失败时仍有首页降级路径。
- 请求版本保护使迟到的登录成功、失败或资料查询不能把已退出用户重新登录、弹提示或带回资料页。
- 登录后的资料页新增首屏“暂不完善，先浏览”。跳过不提交未保存的表单，保留登录身份，清理待继续动作。已发出的保存无法撤回，但迟到结果和延时回跳不会继续导航或预约。
- 主动登录的协议勾选要求，以及发布、加入等业务原有资料要求保持有效。

## 验证结果

- 全量 `node --test tests/*.test.cjs`：**731/731通过**，其中新增登录/导航和资料页退出专项20项。
- 两个页面的WXML编译摘要成功。实际开发者工具加载并显示新游客按钮。
- 实际点击验证：协议未勾选→游客按钮→首页，身份保持guest；公开列表正常加载并进入行程详情，无自动登录跳转。
- 从列表打开登录页再点击游客按钮：返回原列表、待继续动作为空。
- 从公开详情打开资料页：“暂不完善，先浏览”位于首屏，实际点击后返回详情，没有执行保存。
- 登录/保存中取消、迟到响应、导航失败降级等竞态由真实页面代码的VM测试覆盖；这些场景没有对线上用户发送业务写入。
- 工具打开项目时曾短暂白屏并返回协议连接中断，随后窗口正常加载，后续编译和实际点击均成功。
- 测试临时切换为游客。开发者工具热重载丢弃了应用内的临时备份；结束时通过只读`getUserInfo`核验现有本地资料的OpenID匹配后恢复原登录身份并回首页，没有使用新的登录请求恢复身份。

## 交付范围

本次为客户端修复，没有部署云函数、上传体验版、提交审核或发布正式版。审核是否通过仍由微信实际复审决定。前一轮地点业务台账的部署待办仍见[原部署清单](place-business-deployment-checklist-2026-09-23.md)。
