# LinkX 拼车论文可行性研究

研究日期：2026-09-22。本目录保留当时的选题、文献、统计论证与聚合证据，不是当前部署手册。文中的“当前”“待实施”和代码行号均属于当时的观察；后续采集实现与后端迁移已有独立维护入口，不能据此判断今天的启用状态或重新搭建一套服务。

工程入口：[采集服务](../../services/analytics-collector/README.md)、[新后端与迁移边界](../../services/backend/README.md)、[唯一后端模型](../../services/backend/SCHEMA.md)。本目录的研究设计不证明正式实验已经开展，也不替代这些实现的协议与运行核验。

## 结论与先读内容

建议主方向：**社区预约拼车中基于自愿时间偏好的候选推荐：从可行选择到实际同行**。先研究用户在自己接受的时间与接送区域内，是否因为更合适的现有车次建议而改善预约和实际同行；司机保持已公布的发车安排。

现有数据适合诊断和设计先导研究，尚不足以直接证明优化收益。已审计3,586条存活司机行程、184条求车及相关聚合信息；主要缺口是明确出行意向、决策时选择集、真实可接受时间范围及实际同行结果。`past`和现存成员关系不能替代成行证明。

本轮整理**30篇独立一手论文，其中14篇读到全文或作者稿的关键方法、数据、实验与限制章节**，其余明确标为部分正文或摘要。已有研究覆盖时间弹性、多选时刻、去中心化选择和微信实验；本方案不以这些概念本身宣称创新。文献覆盖为范围性审查，并非穷尽的系统综述。

先读[选题决定与研究协议](decision-and-protocol.md)，研究测量要求见[小程序补采计划](miniprogram-collection-plan.md)，工程修改使用上面的维护入口。有条件备选是提前确认与便捷取消后的座位再匹配；是否切换由先导证据决定。

## 目标

通过一手文献、当前平台数据和微信小程序实现约束，选择一个值得开展的独立论文方向。交付能够执行的研究设计与补采方案，不以算法复杂程度代替研究贡献。

## 工作范围

- 系统检索预约拼车、时间弹性、自主匹配、信息展示、重复合作、退出与市场实验等研究。
- 记录文献的题目、作者、年份/版本、来源、实际阅读深度、数据与方法、最近先例和对本平台的限制。
- 只读云数据库，保留聚合结果与提取方法，不保存账号、联系方式、具体住址或原始用户数据。
- 区分业务状态、平台配对、经用户确认的实际同行，以及未观测结果。
- 将候选问题与小程序页面、云函数、权限、前台生命周期和用户操作负担逐项对应。
- 制定数据字典、先导研究、正式评估、功效分析与停止/转向条件。

2026-09-22 研究阶段没有部署功能、改写云端业务数据或启动用户实验。此前旧快照和 2026-09-09 备份已按用户要求移至废纸篓，本研究不恢复或依赖这些旧原始文件。

## 研究推进顺序（不是当前工程待办）

1. P0：可靠业务事件、座位口径、事后结果核实。先确认什么是一次预约、退出和成行。
2. P1：可跳过的意向与时间范围、此前曝光、候选与实际展示记录。
3. 安排2–4周诊断先导并完成行程跟进；其中先核对工程数据质量。这不是正式功效所需时长的承诺。
4. 达到数据与产品门槛后，冻结主要结果、推荐政策、随机化和缺失分析；再规划P2推荐评估。

研究设计依靠前台表单、现有列表和回访确认；不以后台定位、读取聊天或离线必达消息为前提。实际采集覆盖必须按实现、正式发布版本和服务端读回核验；不得将技术采集启用等同于研究测量完整或正式实验完成。

## 判断标准

1. 是否有明确且可证伪的问题；最近的已有论文解决了什么。
2. 贡献来自机制、模型、识别或验证中的哪一部分；是否只是换数据复现。
3. 现有数据能否支持目标，关键缺失是否能用小程序低负担补齐。
4. 是否有足够独立样本及可行实验单元；是否存在共享运力与跨期干扰。
5. 结果指标是否真实、可审计，成本和产品风险是否可控。

所有候选暂不视为已确认的文献空白。先导研究时长也不等同于达到正式论文所需样本量。
