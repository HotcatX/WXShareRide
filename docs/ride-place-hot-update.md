# 拼车地点热更新

司机发车、乘客求车与路线列表筛选共用云数据库 `Departure` / `Arrival` 的固定地点配置。已知地点按 Fort Lee、哥大、纽瓦克、JFK、拉瓜迪亚、法拉盛排序；仅展示配置中存在的项目，其余新增项目接在后面。发布页保留“自选”和当前其他人填写的地点。

固定配置使用 5 分钟跨页面缓存，并合并进行中的重复请求。打开地点选择时，如果缓存过期会重新读取；不做持续轮询。首次发布包含此改动的小程序后，后续增删固定地点无需重新发布小程序。当前管理网站没有地点编辑界面，可以通过云数据库管理工具修改配置。

## 修改方式

- 出发地：`Departure`，文档 `b4498fc86903a813018505643bc4ca31`。
- 目的地：`Arrival`，文档 `cd349d8f6903a85901817428411cfbff`。
- 保留现有单文档结构，业务字段名和字段值均使用地点名称，例如 `"纽瓦克": "纽瓦克"`。增加地点使用 `$set`，不要覆盖整个文档或修改 `_id`。
- 旧 `Departure_Request` / `Arrival_Request` 和价格配置保留；本次未修改参考价。

不要向地点文档添加说明、时间戳或数组元字段。已有工具和模板也会读取该文档的字段值。已知六项顺序由客户端统一；云端新增其他地点不需要修改客户端。

筛选和日历兼容历史机场称呼：纽瓦克 / EWR / Newark、JFK / 肯尼迪、拉瓜迪亚 / LGA / LaGuardia，以及法拉盛 / Flushing。机场的具体自选地点（如 EWR Terminal C）继续保留，按机场筛选时也能匹配；不会批量改写历史路线地址。

乘客参考价格在一次查询内兼容固定地点的精确别名，优先匹配完全相同的地点键；具体自选航站楼不使用整个机场的价格。旧 Fort Lee 核心区/全区域价格仍使用原配置键。

## 本次验证

两个地点配置文档已追加四个短名并读回核验。`getTripList` 机场别名匹配已增量部署。379 项测试通过，覆盖缓存到期、跨页面复用、旧别名筛选、日历统计及参考价格。远控确认列表和两种发布模式的六项顺序、自选区域与选择值；乘客选择 Fort Lee → JFK 可读取旧 `JFK机场` 的价格配置。界面改动需发布新的小程序版本。
