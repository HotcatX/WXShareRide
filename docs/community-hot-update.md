# 首页公告与拼车群入口

首页“社区数据”右侧的 `NY / NJ` 已改为“点击加入拼车群”。点击读取最新云端配置并打开通用公告弹窗，不另外创建一个群二维码窗口。公告可展示标题、正文、图片，图片支持长按和用户主动点击查看大图。

自动公告也使用同一个弹窗。本次初始配置关闭自动弹出；手动查看仍开放，且不限次数、不消耗自动展示次数。

## 配置位置与权限

- 云环境：沿用项目现有环境。
- 云数据库：`community_config` 集合，固定文档 `_id: "main"`。
- 读取入口：现有 `marketApi` 的 `communityConfig` 动作，保留正常微信身份校验。不新增云函数。
- 内容只能由有云端管理权限的维护者更新；小程序不提供配置写入接口。数据库不要开放客户端写权限。
- 朋友圈单页预览不会加载或弹出这份公告。

配置结构：

```json
{
  "_id": "main",
  "group": {
    "enabled": true,
    "title": "Fort Lee 拼车群",
    "imageFileID": "替换为本环境云存储图片的 cloud:// 文件 ID",
    "expiresAt": "2026-09-17T00:00:00+08:00"
  },
  "announcement": {
    "enabled": false,
    "id": "carpool-community-2026-09",
    "title": "加入拼车群",
    "body": "欢迎加入 Fort Lee 拼车群，交流出行与拼车信息。\n长按下方二维码查看入群选项。",
    "showGroupImage": true,
    "imageFileID": "",
    "maxShows": 1,
    "intervalHours": 24,
    "startAt": "",
    "endAt": ""
  }
}
```

日期使用带时区的 ISO 时间，或数据库日期/毫秒时间戳。上例根据图片“9 月 17 日前有效”的提示采用北京时间 9 月 17 日零点保守停止展示；图片没有提供具体失效时刻，更新时应填写实际有效期。

## 常用热更

| 需求 | 更新字段 |
| --- | --- |
| 允许自动弹出 | `announcement.enabled: true` |
| 最多自动展示 X 次 | `announcement.maxShows: X`，整数 1–100 |
| 两次自动弹出间隔 | `announcement.intervalHours`，0–8760 小时，默认 24 |
| 关闭自动弹出，保留手动入口 | `announcement.enabled: false` |
| 发布一条新公告，重新记次数 | 换一个新的 `announcement.id`，使用英文字母、数字、下划线或短横线 |
| 改文字 | 更新 `announcement.title` / `body`，正文支持换行 |
| 展示其他公告图 | `showGroupImage: false`，填写 `announcement.imageFileID` |
| 纯文字公告 | `showGroupImage: false`，`imageFileID: ""`，保留非空正文 |
| 更新群二维码 | 上传新图片，替换 `group.imageFileID` 和 `group.expiresAt` |
| 定时启用、下线 | `announcement.startAt` / `endAt`；留空表示该边界不限 |

`enabled` 只控制自动弹出。有效时间与内容校验同时适用于手动和自动展示。`showGroupImage: true` 时使用有效的群图，并且公告不能晚于群二维码到期时间；群图停用、过期或不可读取时不会显示旧码。弹窗在前台停留到有效期结束时，会按服务器时间自动关闭。

次数按“本设备 + 公告 ID”累计，是总上限，不是每次更新后新增次数。修改标题、图片、启停开关不重置计数；同一条公告从 1 次改成 3 次，已看过 1 次的设备还可自动看到 2 次。重装、清除小程序缓存或换设备会重置本地记录，不承诺账号跨设备去重。

`intervalHours: 0` 表示每次重新进入首页可自动展示一次，直到达到上限；不会在一次停留中循环弹出。手动查看及从大图预览返回不追加自动次数。存储异常时不自动弹出，避免无法记次数导致重复打扰。

首页每次进入、下拉刷新和手动点击都会重新读取配置，不持久缓存公告正文或图片 URL。因此，首次发布包含本功能的小程序版本后，更新云端配置不需要重发小程序版本。已停留在页面的用户可下拉刷新；不是实时推送。

## 修改示例

下面是数据库更新内容，使用 `$set` 保留图片等其他配置：

```json
{
  "$set": {
    "announcement.enabled": true,
    "announcement.maxShows": 3,
    "announcement.intervalHours": 24
  }
}
```

优先在独立管理网站 `/admin/` 的“群码与公告”中调整并保存；它会校验版本、保留历史。也可由云端管理工具更新 `community_config` 中 `_id: "main"` 的单条记录。也可以让 Codex 按“将当前公告开启，每台设备最多 3 次，两次间隔 24 小时”执行更新。

群码图片保存在云存储，配置存永久 `cloud://` 文件 ID，接口每次转换为临时 HTTPS 地址。不要把临时下载链接写回配置；更换图片建议使用新的云存储文件路径，避免图片缓存。

## 验证

运行 `node --test tests/*.test.cjs`。新增验证覆盖配置白名单、身份边界、跨环境图片拒绝、时间边界、关闭自动但允许手动、次数与间隔、存储异常、并发点击及离开页面后返回结果不弹窗。

首页入口已通过模拟器布局检查；`marketApi` 已部署，真实云端配置与群码图片读取已验证。公告长图在真机上的布局仍需验收。
