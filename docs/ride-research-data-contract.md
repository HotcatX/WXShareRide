唯一配置及协议来源：[客户端配置](../config/analytics.js)、[客户端事件校验](../utils/analyticsSchema.js)、[服务端事件校验](../services/analytics-collector/src/validation.mjs)、[服务端协议](../services/analytics-collector/src/protocol.mjs)、[表结构迁移](../services/analytics-collector/src/schema.mjs)。运维接口、保留和恢复流程以[采集服务说明](../services/analytics-collector/README.md)为准。

## 当前范围与覆盖

沿用现有隐私声明，不新增隐私同意弹窗、采集按钮或设置页。技术授权状态不能作为用户主动报名研究的证据。已有“是／否”回访不询问成交金额。

客户端 `develop/trial/release` 的配置比例均为100%，适用于符合条件的已登录账号；开发与体验版使用独立测试身份和合成数据标记，正式版使用真实数据模式。访客、服务端未启用或已关闭的账号、未取得有效会话、队列故障和未成功补传均可能没有事件。**100%配置不等于100%用户覆盖或送达率**，旧版和新版须按版本分别统计。

首次服务端状态 `none` 可自动启用；`active` 复用当前授权；`revoked` 不自动重新启用。前台产生的行为先进入本地持久队列，再批量直传采集服务器；业务成功事实另从服务端事务台账异步同步，两者不能互相替代。

## 已接入的行为事件

批次为 `{schemaVersion:1,batchId,events:[...]}`。SDK事件带 `eventId,eventName,schemaVersion,occurredAt,sessionId,data`，以及客户端版本、构建模式、平台和基础库版本等可用上下文。服务端另记接收时间。账号关系来自可信会话，不接受客户端自报OpenID。

| 类别／事件 | 当前实际触发与主要字段 | 解释边界 |
| --- | --- | --- |
| 页面 `page_view` | 首页、拼车列表、发车／求车详情、历史行程；页面名、会话与时间 | 不是完整的全应用页面统计；当前路由没有接入协议中允许的market/profile |
| 搜索 `search_submitted` | 显式修改筛选且选定单一日期；searchId、类型、日期、起终地区、隐藏满员选项 | 自动加载和多日范围不算一次明确搜索；不是独立出行需求或时间弹性 |
| 列表 `result_set_rendered`／`list_snapshot` | selectionSetId、网络／缓存来源、条数、hasMore、候选完整性；有明确搜索关联时另带searchId | 候选快照最多前50条；仅全部候选均可记录且不超过50条时标完整，不能把截断列表当完整机会集 |
| 曝光 `result_card_visible` | 至少半张卡片连续可见1秒；行程ID／类型、位置、selectionSetId和当时快照 | 依赖可见性观察器；渲染不等于曝光，曝光也不证明注意或理解 |
| 点击／详情 `trip_card_clicked`、`detail_viewed` | 行程、列表位置／来源、当时快照；详情来源为列表／历史／分享／其他 | 查看或点击不等于预约或成行 |
| 联系 `contact_action` | 复制微信／电话／Zelle；行程、目标角色、渠道、copy动作及attempt/success/failure | 只证明复制操作；不记录复制内容，不证明实际联系、付款或成交 |
| 地点选择器 `place_picker_*` | 打开、渲染／可见、选择、自选确认／取消、关闭；起终点侧、城市、候选ID／位置／来源、目录／排序／偏好版本、可用榜单快照、圈、缓存年龄 | 可见阶段按至少半项可见，无1秒停留条件；行为事件不传自选地址原文；公开候选由业务路线投影和目录规则另行生成 |
| 回访 `followup_presented/answer/dismissed` | followupId、行程、司机／乘客角色；明确回答yes/no、主动关闭或页面隐藏、默认结果、答案范围及可用牌面价 | 主动点叉按默认yes统计但保留推定来源；不是用户确认。入队成功也不等于服务器已经收到 |
| 旧版诊断 `service_request/client_error` | 新版已移除生成代码，不再包装wx.cloud.callFunction或上报客户端异常 | 旧正式版及已持久化批次仍兼容接收；需发布新版才停止这些来源。历史不删除，原统计不能当完整计费请求量 |
| 引荐 `referral_visit` | 登录后补传有效引荐码、入口与首次观察时间 | 未登录访客不构成完整分母；旧版引荐记录不能直接混作同一份采集器日志 |

行程快照按可用字段记录地点ID、地区、日期／出发分钟、业务版本、余位、数据生成时间及来源、客户端采样时间、参考价整数分与币种。地区包括Fort Lee、哥大、法拉盛、三个机场、LIC、JSQ、Inwood、中城、下城、Queens及other/unknown；标准地点由[地点目录](../utils/placeCatalog.js)统一定义。

价格来自现有牌面价，标为 `listed_reference`；缺失时保持缺失。回访“是”不会将牌面价变成实际成交价。`snapshotAt` 是客户端采样时间，不能替代服务端生成时间或业务发生时间。

## 回访的实际触发限制

[回访控制器](../utils/tripFollowup.js)由[首页](../pages/home/home.js)在本账号历史数据新鲜、页面可见且没有其他弹层时调用；历史页不再主动弹回访。此处描述当前源码，旧版入口须按对应发布版本解释。

- 仅本人参与的发车／求车记录；状态为past或close，排除明确取消、删除或缺失记录，并核对司机／乘客身份。
- 从最晚计划出发时刻算，须超过4小时，最长在出发后7天内，不再等待次日09:00。首页还依赖业务历史数据可用和用户再次打开页面，不保证4小时准时弹出，也不在后台推送。旧 CloudBase 将个人索引延后移入历史的限制属于切库前行为，当前由 PostgreSQL 历史关系接口提供数据。没有真实到达时间，past/close并非物理成行证据。
- 每次前台最多一次，优先最近的未处理行程；本机同账号的同条行程只展示一次，点叉、隐藏页面或中断后不再重复。沿用现有持久状态，旧shown/dismissed/answered也不重问；清除小程序本地数据或换设备不具备跨设备去重保证。
- 司机问“您接到乘客了吗？”，yes表示至少接到一位；乘客问“您坐上车了吗？”，yes仅属于该回答者的预约。不能把司机的yes扩写为全部乘客均履约。
- 展示、关闭和明确回答分别记录；客户端只在持久队列接受后标记回答成功。新客户端主动点叉发`dismissalReason=close, assumedOutcome=yes`及角色范围；切后台／离页发`hidden`，不填默认结果。旧关闭事件不回填yes。牌面价仍是参考价，默认成行不产生支付事实。
- 服务端`operational_followup_outcomes`按账号、行程、角色区分`self_report`、`dismissed_default`、`unanswered`；明确yes/no始终优先于默认yes。运营可按“明确yes＋默认yes”统计，论文应单独报告明确回答与默认值，并检验假设敏感性。线下约90%的估计不等于逐条关闭记录都真实成行。地点圈学习仍只使用明确回答。

服务端另有 `place_followup_population` 保存从可信业务记录推导的合格参与关系、可询问时间和过期时间；历史行保存当时规则，当前资格汇总使用出发后4小时规则。但目前没有完整的“用户有展示机会却未展示的原因／规则版本”事件。版本差异、7天窗口、每次前台上限和不回应均会造成结果缺失与样本选择，不能用已回答者成功率代表全平台。

## 业务事实、OpenID与地址范围

2026-09-30 切库后，发布、加入、接单、退出、剔除、取消和状态变更由 PostgreSQL 事务写入业务事件，并冻结发往采集器的投影，随后由[投递任务](../services/backend/src/analytics/delivery.ts)按真实 ACK 确认。它保存事件ID、动作、服务端事件时间、行程ID／类型／版本、操作者及受影响OpenID、变动前后快照。快照包括原业务地点文本及地点ID、计划时间、状态、牌面价、余位、乘客数量和司机／乘客关系；这是受限业务数据，不是匿名点击流。旧 CloudBase `TripActions` 及其同步器已退役，[旧台账源码](https://github.com/HotcatX/WXShareRide/blob/a82f73b/cloudfunctions/createTrip/businessLedger.js)仅供解释历史记录。

服务端可信桥将当前平台身份的OpenID与采集账号关联，支持本人问题排查及业务联结；行为载荷不另填OpenID、电话、微信号、支付账号或聊天内容。新后端从已认证业务身份生成同一关联；不接受客户端提交别人的OpenID。分析导出应按需要去关联，不能把可回查账号的数据称为完全匿名。

业务事务成功、台账待同步、采集服务器已经接收是不同状态。历史导入 `legacy_snapshot` 只是某时点的状态，不能补造之前的退出和修改。接收器允许 update/cancel 动作不代表旧 CloudBase 历史中每类修改都发过事件；旧台账的外层 reason 也未完整进入采集投影。当前事务事件与冻结投影见[事件实现](../services/backend/src/rides/events.ts)和[投影实现](../services/backend/src/rides/collector-event.ts)，正式切换证据见[切库记录](backend-cutover-2026-09-30.md)。

地点服务另保存目录、业务参与关系、地点确认票、结果与排名快照。热度票按“账号×地点×起终点侧×纽约日”去重，不能当成原始点击次数；圈是平台业务关联，不表示住址。当前真实公开路线中的未知地点通过文本过滤后可自动标记 `published_route` 并进入候选；该标记不是外部公共场所核验。未接纳文本另留私人或待归类状态，具体规则及限制见[地点推荐说明](place-recommendations.md)。

加入行程的上下车点在本机按账号与同方向完整路线记忆，成功加入后保存最近30条路线；下次自动填入，仍可修改。日期不同可复用，反向、多站顺序不同及其他账号不会复用。此本地便捷输入不新增采集事件或请求；提交后按原业务链路保存，失败／取消不会覆盖记忆。

## 协议、兼容与可靠性

当前客户端通过业务后端 `POST /api/v1/analytics/session` 管理采集会话；业务后端调用采集器标准账号桥 `/internal/v1/analytics/accounts`，客户端批次直传 `/v1/batches`。旧客户端的 `statistics` 云入口按保留协议兼容。标准purpose/notice/JWT标识由[protocol.mjs](../services/analytics-collector/src/protocol.mjs)定义。旧客户端wire和本地队列键集中保留在[客户端兼容模块](../utils/compat/analyticsLegacy.js)，服务端旧wire兼容见[legacy.mjs](../services/analytics-collector/src/compat/legacy.mjs)。兼容是同一账号、同一授权和同一批次链，不另建用户或重开关闭状态；历史请求正文、收据hash与身份派生不得因改名改变。

服务端账号桥使用独立HMAC密钥、防重放nonce及版本比较；客户端只持短期Ed25519会话token。批次接收同时核对当前active状态、grant、用途和版本，token未过期也不代表关闭后仍可写入。账号表的正式名称以[schema.mjs](../services/analytics-collector/src/schema.mjs)为准。

客户端队列上限500条／256KiB／7天，每批最多50条／64KiB，前台最小发送间隔15秒、每次前台最多40次上传。不承诺后台持续上传。只有ACK的batchId、hash和条数匹配才出队；丢ACK保留原批次重试。401续期，403停队列并清理，409/422停止自动重试，限流／服务故障退避。跨批eventId去重；重试不能增加观测数，SDK入队成功不能冒充落库成功。

服务端持久化及当前授权校验在SQLite事务中完成后才ACK。真实行为载荷默认保留180天，合成载荷14天；默认本机滚动备份7天，收据、账号状态和业务派生表各有不同保留规则，具体以服务实现及运维说明为准。分析时间窗可能先于物理清理排除过期记录；长期研究需提前制定去关联导出与保留计划，不能假定原始事件永久存在。

不新增停止按钮；本人通过既有客服提出请求后，按[停止采集工具](../services/analytics-collector/ops/stop-collection.md)核验执行服务端停止。仅清本地队列不等于跨设备停止。恢复必须经过隔离gate及关闭状态保护，不能只凭SQLite完整性检查就视为恢复到最新授权状态。

## 尚缺数据与研究解释边界

协议允许但目前无对应真实页面触发的项目包括：`no_suitable_option`、旧事件名 `trip_detail_opened/contact_entry_clicked`（实际使用detail_viewed/contact_action）；搜索的partySize/intentId、结果zeroReason、电话call动作等也不能因schema允许就声称已采集。队列丢失统计尚不能视作完整自动上报的全局分母。

目前已具备曝光—点击—预约业务变化—部分结果自报的关联基础，仍缺明确的独立出行意向及可接受时间范围、完整失败原因、所有决策时刻的完整候选、充分覆盖的结果回访。没有实际付款价、支付证明、连续GPS轨迹、真实联系内容或平台外解决结果。不应由牌面价估计支付意愿，也不应由浏览次数凑独立样本。

当前地点排序是产品规则，不是随机分配实验；没有记录的处理分配与展示概率就不能宣称排序、价格或提醒的因果效果。论文是否足够取决于独立用户／行程／意向、结果覆盖、有效变异和研究设计，不能由事件总数或固定采集天数保证。

## 重复报告与存储

当前源码已移除独立客户端诊断包装，保留研究所需的候选集合、真正曝光、选择、联系、事务事实、角色区分的明确／默认结果，以及页面访问分母。相同可见访问中完全不变的列表恢复不重复发整份候选／曝光；新一轮网络列表读取成功、筛选、查询、来源、服务端数据生成时间、内容／顺序变化及重新进入页面仍产生新的机会记录。不按日限额或随机抽样删掉真实曝光分母。

采集器按需要无损压缩落库载荷，读取时解码；原始上传字节的hash、收据、ACK及去重关系不变。压缩不会合并不同访问或删除研究事件。已发布旧客户端和旧持久队列仍按兼容协议接收；客户端报告减少须随包含该代码的版本生效，不能由本地源码推断实际节省率。存储格式、备份和恢复操作统一见[采集服务说明](../services/analytics-collector/README.md)。
