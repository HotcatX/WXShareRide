# 个人拼车计次

`syncTripStatus` 与 `syncMyTripStatus` 共用相同的 `rideCompletion.js`，复用现有云函数。页面继续读取 `rideStats.completedDriverTrips` / `completedPassengerTrips`，不更改零值的显示方式。

## 计数口径

- 一条行程按集合名和文档 ID 唯一标识；同一账号在该行程只计一次。
- 正文为 `past` 或历史 `close`，最后出发时间已过，且存在可识别的司机和至少一名乘客才计次。取消、删除、未知状态、未接单请求及空车发布不计。
- `past` 沿用现有业务含义：系统判定行程时间已过，并非额外验证实际到达或付款。
- 以正文的有效成员字段为准。请求创建者是乘客；一个账号占多个座位仍只计一次。不会从人数或历史列表反推身份。
- 完成时的计数留存；之后退出、删除行程或更换角色不撤销已确认的次数，也不重复计数。

## 路线详情的司机统计

路线详情顶部单行展示“已发车 X 次 · 评分 X”。次数使用同一 `completedDriverTrips` 字段，遵循上述完成口径，不把仅发布、未完成的路线算入。缺少次数或有效评分时显示“无”，真实零次显示“0 次”。评分优先使用司机加权平均分，再回退普通平均分。

现有 `getTripDetail` 返回独立的 `driverStats`，只包含司机完成次数、评分次数及司机均分。普通浏览者不获得司机联系方式；参与者复用原资料查询。前端不增加云函数调用，普通浏览详情时后端多一次按司机 ID 投影查询；统计查询失败仍可查看路线。

## 原子性与重试

每条行程通过数据库事务更新参与者的个人计数和私有 `_rideCompletionV1` 台账，并写入行程结算标记。用户计数、凭证必须一起提交，重试或两个同步入口并发也只计一次。仅以点路径更新计数字段，保留评分等其他 `rideStats` 数据。台账位于 `rideStats` 之外，避免随公开统计接口暴露行程 ID。

全部参与者计数完成后，同一事务保存 `_rideCompletionSettled`、版本、时间和参与者数量。重复同步只需读取这条行程即可跳过，避免每次列表刷新都查询所有历史参与者。有缺档案或计数冲突时不结算，后续仍可补计。此标记代表完成时快照；以后若人工清零用户统计或迁移账号，需要另外核验修复，不能指望普通重放重新建立已结算记录。

个人计次独立于首页 `PublicStats`。已有 `servedStatsCounted` 不能视为个人已计。当前行程须先成功同步和计次，再移入用户历史列表，失败时保留可重试的当前 ID。

缺少用户、同一 OPENID 对应多个档案、旧非零计数无法证明去重关系时，分别报告并保留原值，不创建空白档案、不随意选档案、不直接加上重建数量。

## 历史回填与临时入口清理

本次回填已完成。曾在现有 `syncTripStatus` 内使用临时的 `backfillPersonalStats` 动作，先预演，再按明确 ID 小批处理；没有新增独立云函数。回填入口只计算个人次数，不修改行程状态、用户历史数组和首页服务量。

回填完成后移除此临时动作和处理函数。带有 `action` 的旧脚本请求会在进入正常同步之前直接拒绝，避免旧预演脚本误执行普通状态更新。正常客户端只传行程类型和 ID，继续通过原有两个同步函数自动计次。一次性操作记录及旧代码保留在仓库外的审计备份中，旧回填脚本不应继续运行。

回填前备份两个云函数包/配置，以及行程、用户计数字段和历史 ID。历史 ID 只用于发现与核对候选，缺少正文或身份无法核验的记录跳过。备份及逐用户回填清单包含私有信息，保存在仓库外的受限目录，不提交 Git。
